## Limites et livraison

Les captures responsive et Playwright utilisent des émulations de navigateur ; elles ne remplacent pas le toucher sur un iPad réel. Le champ téléphone actif reste visible dans une fenêtre mobile réduite à 390 × 500 px, mais le clavier natif et la navigation complète au clavier n’ont pas été testés. Le widget canonique garde son thème clair propre ; un autre thème n’est pas exposé. Le zoom navigateur à 200 % n’a pas été vérifié. Une séance de comparaison avec cinq personnes reste nécessaire pour mesurer temps, erreurs et hésitations.

Après le retour visuel à la phase 2, les tests ciblés du widget (21/21) et son typecheck repassent. La capture Playwright post-restauration n’a pas été refaite : le serveur de développement préexistant sur le port 3000 ne répondait pas. Les captures phase 5 ne doivent donc pas servir à juger le rendu actuel.

Aucun commit, PR, déploiement ni essai staging n’a été effectué. Le checkout est actuellement sur `main`, avec de nombreux changements non liés non commités ; il faut isoler le lot UI sur une branche de travail avant l’intégration, puis traiter les sept échecs de la suite large.
