Les [actions secondaires ouvertes](reservations-mobile-actions-ouvertes.png) et la [confirmation d’annulation](reservations-mobile-confirmation-annulation.png) montrent le parcours mobile complet sans glissement. Les actions masquées derrière la carte sortent aussi de l’ordre de tabulation tant qu’elles ne sont pas révélées.

Les autres vues appariées (Salle, widget, états particuliers) sont indexées par le manifeste sous les mêmes noms qu’en phase 0. L’API est interceptée dans le navigateur : les images ne prouvent pas le comportement d’une base réelle. Les tests ciblés couvrent les transitions autorisées, l’échec d’une mutation, le nouvel essai et le contrat de la route de Salle.

La matrice appliquée suit les règles métier actuelles : `PENDING` → confirmer ; `CONFIRMED` sans table → allouer, avec table → installer ; `SEATED` → terminer le service ; états terminaux → lecture seule. Annuler et marquer absent sont secondaires quand la transition est autorisée. L’API valide encore la disponibilité d’une table et la fin du créneau au moment d’installer. Une annulation garde la réservation en `CANCELLED` avec son historique ; le bouton « Retirer » historique, qui la faisait seulement disparaître localement, a été retiré.

Pour reproduire les captures avec un dashboard local sur `http://localhost:3100` : `UI_CAPTURE_PHASE=phase2 node apps/dashboard/scripts/capture-ui-phase0.mjs` depuis la racine. Le script intercepte uniquement des réponses fictives et garde la baseline phase 0 intacte.
